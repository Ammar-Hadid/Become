# Living Season image direction

The owner edits image direction at **Settings → Image Prompts**. The database stores immutable template versions; one published version per image type is selected at package assembly time. Published versions affect future reference-sheet, desktop/phone banner, portrait, and 42 chapter/state/format recipes. They do not rewrite or regenerate an existing image. The first read creates version 1 from the repository's bootstrap definitions; subsequent runtime prompt wording comes from the database.

Every new Season image begins with a selected C.O.T.S., an approved source-grounded character profile, and an owner-approved visual-intent brief. The five brief fields describe intended feeling, demeanor, recognizable anchors, atmosphere, and depictions to avoid. AI may draft them through the central Nexo task when a model is assigned; the owner can always enter and approve them manually. Weak source notes or insufficient visual identity block the draft and new image packages with an actionable explanation. Name, gender, and genre alone do not determine mood.

`resolveSeasonImagePackage` combines the saved AI-written creative direction (for AI-authored guided packs) with mandatory formats, recipe constraints and ordered references. The writer stores the template versions used; reopening or copying preserves those versions. Legacy packs and no-model inspectors can assemble reusable direction without claiming AI authorship. The resolver assembles the versioned visual-language template, the composition-specific template, approved character and Season data, and ordered image references. Its SHA-256 receipt covers the exact text, template versions, references, and identity/profile/brief/intent revisions. The provider receives `package.prompt` without appended creative instructions and the listed references in order. The run and saved asset retain the package. Codex must consume that same package; the Settings preview and Season editor expose text, references, and receipt for manual work. A manual receipt is a claim of using the displayed package, not proof of what an external tool received; every upload still requires human image review.

The Settings workspace starts in a read-only view of the saved text. Intent and Prompt each have their own edit control; Variables and Rules each have a plus control. These actions open or change only their respective section. The variable selector inserts a saved `{{placeholder}}` into the shared prompt editor. The document button in the Current prompt header saves all current changes as a versioned draft, including an unchanged copy of a published template; publishing that draft makes it the recipe for future generations. Intent and rules are included in the exact assembled prompt, and variables resolve from the selected Season's approved character and art data. Existing templates retain their original body until the owner chooses to separate instructions into intent or rules. Drafts and published versions can be inspected without spending provider budget.

The prompt inspector assembles the exact package for a real selected Season and imagery type, showing its prompt, references, versions, and receipt. Scene types also require a chapter. If the selected Season lacks an approved character profile or visual-intent brief, the inspector names that prerequisite rather than inventing character traits. There are no fictional preview personalities or separate staging receipts. The Settings action for existing imagery opens the selected Season's review workspace, where the owner can generate or upload replacement art using the published package. New revisions remain in review while previously approved art stays visible. Asset approval, rather than prompt publication, switches what viewers see.

The defaults distinguish dramatic composition from a prescribed emotion: depth, detailed environment, clear identity, and protected copy areas can express stern discipline or warm support. Published template history and per-asset receipts preserve which recipe produced each image. Reusing a seed or a single reference character cannot guarantee model output; the owner reviews each result for identity, tone, and legibility.

The admitted library groups Shared style, Banners, Portrait and Chapters, with one selected recipe editor. Chapters select 1–7, desktop/mobile and pace. Original six generic recipe histories remain stored; the additive migration copies their owner-published text and saved draft into new chapter keys without overwriting existing chapter edits. The exact prompt Drawer uses Living Ink and primary-button success feedback; reference downloads follow the exact package order. Prompt writing and manual uploads are separate from image generation.
