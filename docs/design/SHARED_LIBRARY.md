The implementation lives in `src/components/ui/`, `src/components/layout/`, and `src/app/styles/tokens.css`; this file is an index, not a second implementation. Product-specific facts, actions, persistence, and copy stay with their features. `AGENTS.md` makes reuse and the admission rule mandatory for every agent.

## Mandatory admission workflow

1. **Search first.** Identify the role and inspect this inventory, the applicable design document, and the actual shared implementation. Use an existing approved treatment when it fits. Do not create a parallel feature component, CSS treatment, timing, or cue to avoid using the library.
2. **Isolate a genuine gap.** If a new user-facing component, style, interaction, motion, or sound is needed—or an existing approved treatment needs a visible or audible change—build the candidate on its **own separate preview page**. A candidate may reuse existing shared pieces, but its novel treatment remains outside the approved library and outside production feature screens. Include realistic content, relevant states, desktop and phone layouts, keyboard behavior, and reduced-motion or muted behavior where relevant.
3. **Present the actual preview.** Show the working page to the product owner and ask exactly: **“Do you like it?”** Describe what would be admitted. Do not ask based only on a plan or an unrendered proposal.
4. **Wait for explicit approval.** A clear approval of that candidate is required. Silence, elapsed time, lack of objection, and approval of a different candidate do not qualify. Record the approved version and usage rules in `docs/design/`.
5. **Promote, then consume.** Move the approved implementation to the appropriate shared owner, put recurring values in approved tokens/config, verify responsive/accessibility behavior, and only then use it in the owning feature. If rejected, revise only on the preview page and repeat the question. Do not silently ship an alternative.

This gate also applies to extensions of shared components. A bug fix that preserves an approved treatment, domain logic, data binding, and reuse of an already approved variant can proceed without a new preview. New typography treatments use the same candidate gate; approved values remain editable in `tokens.css`.

## Completion check for user-facing work

Before calling a feature complete, verify that every visual, interactive, motion, and sound treatment is either an exact reuse of this inventory or has completed the preview → explicit approval → shared-library promotion sequence. Verify that a candidate route is not referenced by production navigation, and that no unapproved candidate was imported into a feature. Preserve feature-owned data and save semantics while sharing presentation and interaction primitives.

The compact `RecognizedCharacter` and edition `VersionDrawer` are approved for connected onboarding. See [RECOGNIZED_CHARACTER.md](RECOGNIZED_CHARACTER.md). Preparation has three steps; recognition is inline and authentic-image review remains required before artwork.
